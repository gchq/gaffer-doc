# Gaffer 2.4.0 Changelist

Below are a list of the potentially breaking changes added in Gaffer version
2.4.0. A list of all changes in this version [can be found on GitHub](https://github.com/gchq/Gaffer/releases/tag/gaffer2-2.4.0).
This page covers only changes which may impact existing Gaffer installations.

Please note that the most significant changes have been to the federated store.
This page is aimed at users updating from a previous 2.x version to a 2.4.x
release.

## Federated Store Changes

!!! danger "Breaking Change"

A significant overhaul of federation has been done for 2.4.0, this has been
developed without effecting the existing federated store under the name
"simple federated store".

During versions 2.3.x two stores have existed for federation under different
class paths, the existing store at: `uk.gov.gchq.gaffer.federatedstore` and the
new one at: `uk.gov.gchq.gaffer.federated.simple`. The main change of 2.4.0 is
to move the classes under the "simple" federated store into the existing
federated store module replacing the existing store.

### Differences in Queries

The main goal was to simplify federated queries to this respect the biggest
change for a user is that a `FederatedOperation` no longer exists. All
federation specific control on an operation is now done through operation
options which have been documented in the [reference guide](../../reference/operation-options/federated-options.md).

!!! example ""
    How to specify graph IDs and aggregate common elements between graphs.

    === "Old"
        ```json
        {
            "class": "uk.gov.gchq.gaffer.federatedstore.operation.FederatedOperation",
            "graphIds": [
                "graph1",
                "graph2"
            ],
            "mergeFunction": {
                "class": "uk.gov.gchq.gaffer.federatedstore.util.ApplyViewToElementsFunction"
            },
            "operation": {
                "class": "OperationChain",
                "operations": [
                    {
                        "class": "GetAllElements"
                    }
                ]
            }
        }
        ```

    === "New"
        ```json
        {
            "class": "OperationChain",
            "options": {
                "federated.graphIds": "graph1,graph2",
                "federated.aggregateElements": true
            },
            "operations": [
                {
                    "class": "GetAllElements"
                }
            ]
        }
        ```

Merging from a user perspective has also been improved to give users much more
control over how the data from multiple graphs is merged together (if at all).
A new [user guide is available](../../user-guide/query/gaffer-syntax/federated-queries.md)
to help understand this.

### Differences in Deployment and Admin

Changes for deploying and administrating graphs has been kept similar where
applicable however, a range of store properties are available to configure
defaults for merge operations and default graph IDs. A full list of all store
properties are documented in the [reference guide](../../reference/store-properties/federated-store.md).

Slight changes to adding and removing graphs has been made. This largely is to
consolidate the functionality the was previously in multiple operations. A list
of operations and how they differ are in the table below:

| Operation | Still Exists | Changed |
| --- | --- | --- |
| `AddGraph` | Yes | Slight changes to the available options. You can now specify the full graph config JSON in the operation this includes Graph Hooks, Graph ID etc. A `graphAuths` option is no longer available please see the admin guide for details on [access control](../../administration-guide/gaffer-stores/federated/access-control.md). |
| `AddGraphWithHooks` | No | Functionality migrated to `AddGraph`. |
| `ChangeGraphAccess` | Yes | Functionally the same but changes made to reflect the differences in access control. Can now change the `readPredicate` and `writePredicate` on a graph too. |
| `ChangeGraphId` | Yes | No change. |
| `FederatedOperation` | No | See [query changes section](#differences-in-queries). |
| `GetAllGraphIds` | Yes | No change. |
| `GetAllGraphInfo` | Yes | Data returned has been expanded. |
| `RemoveGraph` | Yes | Additional boolean option `deleteAllData`. |
| `RemoveGraphAndDeleteAllData` | No | Functionality migrated to `RemoveGraph`. |

How graphs are stored in the graph cache has been simplified and is likely not
compatible with existing versions. All graphs added to a federated store in 2.4.x
are always stored in the default cache implementation, more details on the cache
changes can be found in the [new admin guide](../../administration-guide/gaffer-stores/federated/configuration.md).
